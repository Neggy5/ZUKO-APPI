# ZUKO API yt-dlp / YouTube fix — 2026-09-22

## Changes

- Updated `api/Dockerfile` to install `yt-dlp[default]` together with the matching `yt-dlp-ejs` package.
- Kept Node 22 as the JavaScript runtime required by current yt-dlp EJS support.
- Added `YTDLP_JS_RUNTIMES=node` to the container environment.
- Updated `api/lib/ytdlp.js` so every yt-dlp invocation explicitly enables the configured JavaScript runtime with `--js-runtimes`.
- Applied the runtime setting to metadata/format inspection and actual audio/video downloads.
- Kept the existing `/v1/ytmp3`, `/v1/ytmp4`, `/v1/download/audio`, and `/v1/download/video` route files unchanged.
- Kept the existing URL validation, public-host SSRF protection, file-size limit, timeout, streaming and cleanup behavior unchanged.

## Why

Railway logs showed yt-dlp running without a supported JavaScript runtime and then failing YouTube extraction with `Sign in to confirm you're not a bot`. Current yt-dlp EJS setup requires a supported JavaScript runtime for full YouTube support; Node 22 is supported and must be explicitly enabled when used instead of the default Deno runtime.

## Deployment

Rebuild the Docker image so the updated Python packages are installed. No new Railway environment variable is required because `YTDLP_JS_RUNTIMES=node` is supplied by the Dockerfile.

If you override `YTDLP_JS_RUNTIMES` in Railway, use `node` (or an explicit Node path) unless you intentionally configure another supported runtime.

## Cobalt tunnel streaming patch

- Replaced the Node `fetch()` tunnel-to-file reader with native HTTP/HTTPS streaming.
- Added redirect handling, response-type validation, timeout handling, backpressure, and byte counting.
- This specifically addresses Cobalt returning HTTP 200 while ZUKO received a zero-byte/JSON response.
